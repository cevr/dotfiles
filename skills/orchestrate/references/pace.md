# Pace: the Claude pool and the Codex account

Read this before a wave, and when an `Agent` call is held or a Codex turn is latched.

- **Claude agents across every host on the account pool run at the pool's pace. The budget alone sets how many run at once; the skill sets no count.** The pace spends 99% of every account before its weekly reset at an even rate, and keeps each account under 90% of its 5-hour window. Each agent kind's cost per active hour comes from its own transcripts over 7 days, per project; a session's project is its herdr workspace's name, or what `/pool project <name>` sets. The `guard-agent` hook (`claude/hooks/guard-agent.ts` in dotfiles) asks `budget.ts --admit` before each `Agent` call. Every call waits its turn in one agent queue across all hosts (`budget/queue.ts`): the session that runs the fewest agents goes first, then the earliest request, so open sessions share the pace evenly. The agent starts when its turn comes and its expected cost fits the pace. **A held call is queued, not refused for good.** The hold names a ticket and a waiter command: run `bun budget.ts --wait <ticket>` with `run_in_background`, and go on with other work. When it exits 0, call `Agent` again at once with the same `subagent_type` and description; the grant holds 5 minutes. Exit 3 means the ticket lapsed: call `Agent` again to queue it anew. Set no timer, poll nothing, and keep the waiter running: a ticket with no waiter for 2 minutes leaves the queue. Before a wave, run `bun ~/.claude/skills/orchestrate/scripts/budget.ts` for the pace and `--costs` for what each kind costs; `--burn` shows where every host's tokens went over 7 days (what the context held, each kind's start and mean context) and which levers cut the most. Settings live in `~/.config/orchestrate/budget.json`, a link to `orchestrate/budget.json` in dotfiles on every host, so change them there and pull on each host (`budget/pace.ts` holds the defaults). Codex Counsel runs do not count. A heavy agent runs a gate or a browser: every implementor and verifier, and a reviewer that runs probes. Time the gate once before the first wave. Before starting a heavy agent, read the load (`sysctl -n vm.loadavg` or `uptime`), and start none while it is above the core count. While a gate waits longer than twice its own run, start no new unit, and make gate speed the next unit.

- **Codex threads run at the Codex account's pace.** The bridge starts every turn, a thread's first or a next one, only when `budget.ts --codex --admit` finds room in the account's burn (the even weekly line decides when it cannot measure). A held turn is latched, not refused: `start` or `send` returns at once, the turn starts by itself when there is room (next turns before new threads), and its end arrives as a message like any, so do not retry or poll it; past 10 minutes it moves to Claude ([`hosts.md`](hosts.md), Families); `budget.ts --codex` prints the cost of 1% of the week, the pace and the burn now. An early reset can change what 1% costs (on 2026-10-27 sol's nearly doubled), so the fit uses the current reset period once it has 8 windows, and the last 7 days until then.

- **Cache and budget.** Subagent caches last 5 minutes; keep that TTL. A gap longer than that rewrites the context once. A Claude turn costs about 28k weighted tokens whatever the role or effort, so cost is turns: plan a week below the 6.3B weighted tokens that hit this pool's limit ten times in the week of 2026-10-13. Keep each worker small: one concern per unit, delta rounds, messages that carry paths and not content, gate output in logs, and stop a unit's agents when it closes.

## Resume after a limit

**Resume on your own after a limit** (owner, 2026-10-24). While any step is `stuck(quota)`, keep one background Bash command armed that waits until `bun ~/.claude/skills/orchestrate/scripts/budget.ts --resume-at` prints a time that has passed, then exits. Its exit wakes you, and you rerun every `stuck(quota)` step. Arm it before you end a turn on a limit, so the run never waits for the owner. In the week of 2026-10-17, the owner typed "continue, rate limit is up" 6 times.
