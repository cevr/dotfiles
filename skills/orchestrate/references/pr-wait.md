# Waiting on a team approval

Where main changes only through a PR that a teammate approves (a team repo, `Lands: PR`), an accepted unit still queues in `ready` and is gated with its batch: the batch gate runs once, locally, on the merged batch, and main is never pushed. Once the batch gate is green, the unit's own branch is pushed and its PR opened or updated (`create-pr`), CI on the PR is started as the spec's `CI` line names (Land a batch, step 4), and the unit goes to `waiting(pr)`. It holds no slot: start the next unit. Run one background until-loop on `gh pr view <n> --json reviewDecision,state` that exits when either changes. Approved with CI green on the PR's current head, or merged: back to decide. Changes requested, or a red CI run: the comments or failures go to a fresh implementor as the next round (a red CI run is a fix unit, Land a batch step 5), and its branch is gated in the next batch before it is pushed again. Without the `waiting(pr)` state, the wait for approvals reads as time spent in decide, and the logs cannot tell it from work.
