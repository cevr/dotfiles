# How a step ends

Generated by `scripts/ending.ts` from its two functions: edit that, then run `scripts/agents.ts`. F1 gives each item's label from its own state; F2 gives the verdict and its files from the item states present, and the evidence from why the step stopped. Each role's prompt carries its own tables, as below.

## planner

**How your step ends.** It stops the moment a refusal comes (the Refusals paragraph) or the round's limit passes; else it goes on until no runnable item is left. Each item is in exactly one state, the one whose facts it has (first table; each fact is decided by the item's own history: what its attempts printed, and what it can do now), and that state, with whether runnable work was attempted, gives its label, whatever stopped the step. The states present give your verdict and its files (second table), and why the step stopped gives the evidence they hold. Effort is no state and no label. Assigned work is the spec items; whatever else you find is not assigned. Your required work: every section of the spec filled, and its acceptance check runnable and recorded red. You never implement, so the product behavior its Done line names stays unbuilt and is no item left.

| State | An item that is | Its label |
| --- | --- | --- |
| done | assigned, its acceptance holds | none: it is no item left |
| runnable | assigned, required, can still advance in this lane, attempted or not | `continues next round`: this unit's work, in its next round (or its rewrite after the failure cap); never a follow-up, when never attempted; once attempted, `continues next round`: this unit's work, in its next round (or its rewrite after the failure cap); never a follow-up; name what its last attempt printed |
| waiting | assigned, required, waits on an open unit, question, commitment or two contradicting spec lines | `waits on <id>` |
| refused | assigned, required, a refusal stopped it | `refused: <what>`, adding `; form: <the form it named>` only when the refusal named one: this unit's work, never a follow-up, never tried another way |
| cannot run | assigned, required, this host cannot run it (its check or tool is absent or will not start), with no refusal | `cannot run here: <check or tool>`, with its command and output |
| a discovery | not assigned | `finding outside the unit`, under Follow-ups in your file |

| Verdict, the first that holds | When | You write |
| --- | --- | --- |
| `ready` | every item is done or a discovery | `<unit dir>/spec.md` |
| `blocked` | otherwise | `<unit dir>/state.md` current (even with no commit since) and `<unit dir>/blocked.md`: the stop's evidence, and each item left with its label |

The stop's evidence: a refusal named an accepted form: what was refused and the form it named (the exact `!` command or allow rule, as Refusals says); a refusal named no accepted form: what was refused, as the refusal said it, and an allow rule only if one exists; the round's limit passed: the clock (the timebox) or the count (the failure cap); no runnable item is left: what you tried for each item that holds the step back, the options and your pick.

## verifier

**How your step ends.** It stops the moment a refusal comes (the Refusals paragraph); else it goes on until no runnable item is left. Each item is in exactly one state, the one whose facts it has (first table; each fact is decided by the item's own history: what its attempts printed, and what it can do now), and that state, with whether runnable work was attempted, gives its label, whatever stopped the step. The states present give your verdict and its files (second table; an optional probe is only ever done, proven or unproven, and unproven never changes it), and why the step stopped gives the evidence they hold. Effort is no state and no label. Assigned work is the checks of step 1, which are required, and the wider probes you run, which are optional; whatever else you find is not assigned. Your required work: every check of step 1 ran to a result that settles pass or fail, for every unit; a check of step 1 that could not run or ran unclear is `stuck`, never `accepted`, and a wider probe this host cannot run goes under Unproven and does not stop `accepted`. Before any unit, a `Heads: dotfiles=<sha> fork=<sha>` line must name your head and its fork commit (`git rev-parse`), else the batch is `stuck`. The batch: `stuck` on a wrong heads line, else `accepted` if every unit is, `changes` if any is, else `stuck`.

| State | An item that is | Its label |
| --- | --- | --- |
| done | assigned, ran and passed | none: it is no item left |
| proven | assigned, ran and proves a Blocker or Major | a Blocker or Major, filed with its proof |
| runnable | assigned, required, can still advance in this lane, attempted or not | `not run`, named under Check, when never attempted; once attempted, `retry: <check>`, named under Check with what its last attempt printed; it continues to a result |
| waiting | assigned, required, waits on an open unit, question, commitment or two contradicting spec lines | `waits on <id>` |
| refused | assigned, required, a refusal stopped it | `refused: <what>`, adding `; form: <the form it named>` only when the refusal named one: never tried another way |
| cannot run | assigned, required, this host cannot run it (its check or tool is absent or will not start), with no refusal | `cannot run here: <check or tool>`, with its command and output |
| ran unclear | assigned, required, ran, with a result that settles neither pass nor fail, and no retry can settle it here | `ran unclear: <check>`, with its command and the output that settles nothing |
| unproven | assigned, optional (a wider probe), not passed, proving nothing | `unproven: <probe>`, under Unproven with the probe that would settle it; it never changes the verdict |
| a unit finding | not assigned, the unit's change introduced it, shown by measured attribution (whether or not a spec item names it) | marked `unit`: the same lane closes it in its next round |
| a base finding | not assigned, shown on the base head too | marked `base`: a follow-up unit |

| Verdict, the first that holds | When | You write |
| --- | --- | --- |
| `stuck` | any item is runnable, waiting, refused, cannot run or ran unclear | each unit's `round-N-findings.md` and the batch's findings file; under Check, the stop's evidence, and each item left with its label |
| `changes` | any item is proven | each unit's `round-N-findings.md` and the batch's findings file; under Check, the stop's evidence, and each item left with its label |
| `accepted` | otherwise | each unit's `round-N-findings.md` and the batch's findings file; under Check, the stop's evidence, and each item left with its label |

The stop's evidence: a refusal named an accepted form: what was refused and the form it named (the exact `!` command or allow rule, as Refusals says); a refusal named no accepted form: what was refused, as the refusal said it, and an allow rule only if one exists; no runnable item is left: each check that holds the verdict back, with its command and exit code.
