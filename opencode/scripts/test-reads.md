# Test runtime inputs

The gate discovers the full unit, acceptance and workbox populations through the same functions the runners use. `bun scripts/check-test-reads.ts --files` lists that union. `--inventory` adds inferred patterns, classification, opaque sites, and enforced patterns.

The checker follows reachable local imports (including re-exports) and reports the actual read site. Static paths and literal globs feed selection directly. Do not add a declaration for an inferred input or for a pure imported function.

A computed path is not bounded by `join("fixtures", input)`: `input` could contain `..`. Wrap its operand in `matchingInput("fixtures/**", file)` and add `// @reads-indirect fixtures/**`. For a bounded non-directory glob, use `// @reads fixtures/*.json`. The checker requires the same scope as the runtime helper. The helper rejects paths outside that scope and symlink aliases; it does not turn an entire checkout into a named scope. Use a scratch-only helper for output created by a test.

Paths are expressed from `opencode/`: `scripts/gate.ts` is inside; `../linux/hetzner-workbox/**` names the sibling directory. An inner glob never matches a sibling merely because it has a leading `**`. Merge sees the full repository diff, using both names of a rename; this does not extend lint, debt or typecheck's scope.

Every runner test can be selected by a change to itself or a known or observed input. Acceptance files and swarm suites keep their own legs; the merge test leg includes fixed-seed unit tests outside the swarm. The latter select on source reach, checked scopes and exact paths in `merge-unit-observations.json` (generated from the independently checked runtime trace). An observed path is positive evidence only; it neither gives unknown sites a scope nor proves an unobserved read cannot happen.

The conservative fallback is `// @reads all` and `// @reads-reason <reported kind> at <file>: <opaque operation>`. It makes a merge-eligible suite run on every nonempty repository diff, and invalidates an unknown unit or acceptance cache key on every new Git head. Use an enforced bound when the subject is narrower than the whole checkout. A child with unresolved inputs is not whole-tree discovery; keep it unknown rather than declaring a scope its descendants can leave.

For subprocesses, a checkout filename in argv is an input, not a claim that all descendant opens were observed. The checker models fixed command/operand forms and treats opaque argv, unmodeled commands and shell programs conservatively. The preload used to check coverage sees instrumented JavaScript operations and argv, but cannot see native descendant or loader opens.

The scratch fixture adapters are an exception to that tracing limit. Their normal runs check the cwd, tool and operands, discard environment overrides, and refuse generated programs (including shims) that name the checkout. A guarded Git fetch first checks the configured remote resolves to a scratch path; the generated Bun JUnit runner takes explicit suite names and an output path, not checkout discovery options. During the Mac inventory, a separate native policy denies file reads under the checkout and a live audit records attempts, including descendants. The controls must prove the audit can see a denial. This is an accident check for our fixtures, not containment of an adversarial child.

A self-contained checkout shell entry is read by its exact name, then run as a scratch fixture. Do not use this form for a script that needs checkout-relative neighbors. For checked Bun launchers (plain, reaper-owned, or detached), name the checkout entry and separate scratch arguments and state from any checked external installation or checkout operand. The checker follows the entry's initialization and `import.meta.main` branch; an opaque read in that closure still makes the caller unknown. Finite `import()`, `require()` and `Bun.resolveSync` expressions resolve each candidate; unresolved choices remain opaque.
